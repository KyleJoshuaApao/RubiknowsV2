- **vercel-php versions tested:** `0.8.0`, `0.9.0`
- **Node.js version tested:** `22.x` (also reproducible with platform default `24.x`)

## Expected behavior

The generated `launcher.js` should be loaded and its exported `launcher` handler invoked.

## Actual behavior

The Vercel Rust/Node bootstrap (`/opt/rust/nodejs.js`, part of the 2026-08-10 Vercel Managed Images rollout) appears to import the complete handler string `launcher.launcher` as a **literal ESM file path**:

```text
/var/task/launcher.launcher
```

The current runtime source creates `launcher.js` in `getLauncherFiles()` and configures the Lambda handler as `launcher.launcher`:

- `src/utils.ts` — `getLauncherFiles()` produces `launcher.js` (from `launchers/builtin.js`)
- `src/index.ts` — `new Lambda({ handler: 'launcher.launcher', ... })`

This is the AWS Lambda `<module>.<export>` handler convention (`launcher.js` → export `launcher`). The previous Vercel Node bootstrap understood this convention and resolved it to `launcher.js`. The new Rust bootstrap appears to treat the entire `launcher.launcher` string as an ESM module specifier and tries to `import()` the file `/var/task/launcher.launcher`, which does not exist.

## Root cause analysis (inference from stack trace)

1. `getLauncherFiles()` in [`src/utils.ts`](https://github.com/vercel-community/php/blob/master/src/utils.ts) emits `launcher.js` into the Lambda bundle.
2. `build()` in [`src/index.ts`](https://github.com/vercel-community/php/blob/master/src/index.ts) sets `handler: 'launcher.launcher'` — the AWS-style `<module>.<export>` format.
3. The new Vercel Rust runtime (`/opt/rust/nodejs.js`, rolled out with [Vercel Managed Images on 2026-08-10](https://vercel.com/changelog/vercel-sandbox-managed-images)) no longer parses the `<module>.<export>` convention. It interprets the handler string as an ESM module path and attempts `import('/var/task/launcher.launcher')`, which fails with `ERR_MODULE_NOT_FOUND`.

This is an inference from the stack trace, not a confirmed Vercel platform change. However, the timing (first observed 2026-08-12) aligns with the Vercel Managed Images rollout, and the error message clearly shows the bootstrap treating `launcher.launcher` as a file path rather than a `module.export` pair.

## Troubleshooting already completed

- Upgraded `vercel-php@0.8.0` → `0.9.0` — **same error persists**
- Forced fresh Preview and Production deployments (`vercel --prod --force`) — **same error**
- Pinned Node.js to `22.x` via `.nvmrc` (vercel-php's documented supported version) — **same error** (the Rust bootstrap is platform-level, not Node-version-dependent)
- Confirmed the crash occurs **before** application code runs (no PHP/Laravel logs)
- Confirmed Vercel project has **no Dashboard-configured environment variables** (all from `vercel.json` `env` block, applies to both Preview and Production) — **not an env var issue**
- Verified both `sin1` Production and Preview deployments exhibit identical behavior
